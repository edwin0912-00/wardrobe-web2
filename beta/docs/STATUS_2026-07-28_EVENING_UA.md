## 4. Питання на дошку — для codex-main, продовжити без мене

Ці чотири пункти висіли в `ops/RUNTIME.json.blockers` без власника ще з учора.
Ставлю їх прямо, щоб не переоткривати:

1. **Розмір релізу (325 MiB проти 160 MiB).** Хто вирішує — добудувати повні
   пакети для 11 нових `std.*` пресетів (реєстри прав + платні lighting preview)
   чи відкликати їх у кандидати? Без рішення жоден реліз не пройде верифікацію
   і жоден деплой з гілки неможливий.
2. **Розділення за презентацією (чоловік/жінка) — усе ще `unassigned`.** Поле
   `compatibility` у двох чоловічих style-units лежить мертвим, жоден код його
   не читає. Наслідок незмінний від учора: жіночі стилі пропонуються чоловічим
   образам. Хто бере цей рядок?
3. **`/api/editorial-modes` досі не розрізняє `shoot.*` і легасі `editorial.*`
   в одному списку.** `unassigned`.
4. **`/api/health` досі повертає булеве значення часу конструювання**, тому
   недоступність провайдера невидима. Це не те саме, що
   `BETA-HEALTH-SEMANTICS-001` в opencloud — перевір, чи вони насправді
   перекриваються, чи це два різні дефекти.

Плюс п'ять відкритих рішень з минулого хендофу, досі без відповіді: прозорий
аватар (звідки ключ), планка повноти образу для Live, м'яке видалення замість
підтверджень, Live 60с проти `max_session_seconds: 5` у конфізі, і чия сторона
канонічна для розбіжних хешів прав/теракоти.

## 5. Найшвидший шлях до реального тестування на beta

Пряма відповідь на пряме питання. Порядок, що розблоковує найбільше:

1. **Спочатку розмір релізу.** Без цього деплой з гілки взагалі неможливий —
   решта не має значення, поки `verify-product-release` не проходить.
2. **`ops/runtime.mjs --verify` перед активацією** — секунда, ловить розсинхрон
   каталогу, який уже двічі стався в різні боки.
3. **Один наскрізний прогін живою рукою** (не тестом): завантажити фото →
   аватар → речі → образ → один стиль → один відео-кліп. Перший реальний прогін
   від людини ще не записаний ніде — усе, що є, це фокусні тести.
4. Мейнсайт (продакшн-домен) — окремий периметр, і, як ти сам кажеш, найшвидше
   не встигне цього разу. Пріоритет — довести бету до стану, який можна чесно
   назвати робочою мінімальною версією, і саме на ній тестувати.
