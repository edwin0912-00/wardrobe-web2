## Що саме беремо

1. **Повноекранна послідовність секцій.** Один великий змістовний блок за раз;
   на desktop — спокійний вертикальний deck, на телефоні — ті самі блоки без
   приховування критичної інформації.
2. **Один вузол = одна відповідальність.** Input, перетворення, gate,
   збережений артефакт і наступний маршрут не змішуються в одній картці.
3. **Чітка різниця між переходом і перевіркою.** Візуально gate не виглядає як
   ще один генератор: він або пропускає артефакт із evidence, або зупиняє його
   з конкретною причиною.
4. **Лінії зв'язку та поступова анімація.** Вони показують порядок і активний
   маршрут, а не декоративну «думку моделі». Якщо браузер має reduced-motion,
   схема залишається повністю читабельною без анімації.
5. **Панель фактичного стану.** У фінальному продукті цифри, hash, QA verdict,
   job/status та наступна дія беруться тільки з receipt/runtime, ніколи не з
   зашитого макета.
6. **Фінальна повна карта.** Наприкінці — єдина схема всіх доступних блоків і
   їхніх розгалужень, але лише з реально увімкненими маршрутами; unavailable
   маршрути мають бути позначені саме як unavailable.

## Як це накладається на наш продукт

Фінальна карта не зобов'язана повторювати приклад буквально. Актуальні блоки:

```text
Input → Avatar → Selected items → Master look → QA → Saved look
                                      ├─ Improve look candidate → QA → candidate
                                      ├─ Standard background → Scene QA → scene result
                                      │                              └─ Scene video: product focus | posing
                                      ├─ Create Universe photoshoot → hero → series → contact sheet
                                      ├─ Fashion Video → clip QA → saved clip
                                      └─ Real-time Look → explicit camera consent/session
```

`Improve look` та `Scene video` уже затверджені як продуктові гілки, але їхні
генераційні server routes ще не реалізовані. На фінальній карті їх можна
показувати як заплановані модулі, але не як completed/running.

## Межа для beta зараз

Поточний `#pipeline-nodes` показує виконання конкретного run. Цей deck має
з'явитися **після результату** як зрозумілий підсумок pipeline, а не замінити
live execution graph. Спершу прив'язати кожен його статус до реального
receipt; потім переносити дизайн у main-клієнтський сайт.
