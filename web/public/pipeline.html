01

Наскрізний flow

Кожна стрілка має typed input/output; failure не обходить gate.

LIVE · CLIENT1. Web UI

Фото людини, необов’язкове додаткове фото, текст і до 5 фото речей. Кожне поле завантаження має незалежний стан і preview.

LIVE · API2. Fastify intake

Consent, MIME, decode, dimensions, 20 MB/file. Multipart стає нормалізованими upload objects.

LIVE · STORAGE3. Immutable source

Raw bytes записуються один раз в isolated run directory. SHA-256 прив’язує всі наступні artifacts.

LIVE · VLM4. Картка речі

Codex формує строгий JSON: категорія, видимі характеристики, невідомі ознаки, блокери та впевненість. Фото людини напряму лишаються доказами для генерації та QA.

LIVE · LOCAL5. Підготовка референсів

Sharp: EXIF-орієнтація, sRGB, обмежена нормалізація, кадри обличчя/людини, вирізана річ і зображення на білому фоні.

BLOCKING GATE6. Readiness

READY продовжує. REPAIRABLE виконує лише declared repair. NEEDS_INPUT або INCOMPATIBLE зупиняє run.

LIVE · CONTRACT7. Immutable job.json

Paths, hashes, prompt templates, limits, exact outputs і fixed model route. Credentials залишаються поза JSON.

LIVE · CORE8. State machine

Checkpoints, idempotency keys, append-only events, bounded retries і resume без duplicate create.

LIVE · PROVIDER9. Higgsfield adapter

Exact argv: create → atomic journal → wait/resume → validate host/MIME → download PNG.

LIVE · CLOUD MODEL10. Quality route

GPT Image 2 primary. Лише після retryable failure: Nano Banana 2, потім Nano Banana Pro.

BLOCKING GATE11. QA

Exact-white/decode/dimensions окремо від identity, outfit, anatomy, realism та bleed review.

LIVE · EVIDENCE12. Approved result

PNG, exact prompt, manifest, provider receipt, hashes і QA report. SSE повертає чесний progress у UI.

03

Avatar phase

Спочатку затверджуємо канонічну людину.

  1. Identity pack: normalized → face → person.
  2. Prompt: frontal half-body, full face, soft light, exact white.
  3. Generate candidate through attempt 1.
  4. Normalize лише border-connected near-white.
  5. Technical QA + hash-bound semantic QA.
  6. Тільки PASS стає `APPROVED_AVATAR`.
04

Outfit phase

Одяг не має права змінити затверджену людину.

  1. Затверджений аватар завжди є першим референсом.
  2. Далі йдуть докази зовнішності та підготовлені референси речей.
  3. Опис і картка речі фіксують тип, колір, матеріал, логотип і посадку.
  4. QA шукає зміну зовнішності, залишки старого одягу та невідповідність речей.
  5. PASS експортує `avatar_outfit.png` і докази перевірки.
